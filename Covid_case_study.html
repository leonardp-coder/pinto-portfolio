01 · The Engineering Challenge

Why build this platform?

Public health datasets span multiple clinical and demographic domains, arriving in heterogeneous formats and conflicting time grains. The objective was to architect a repeatable, governed pipeline capable of turning raw multi-grain feeds into unified analytical tables.

🎯 Core Engineering Objectives

  • Automate ingestion of cases/deaths, hospital admissions, and population feeds.
  • Structure cloud storage cleanly by business domain and processing maturity.
  • Standardize inconsistent schemas, delimiters, and date formats into reliable tables.
  • Integrate multi-grain facts around shared, reusable dimension tables.
  • Audit and verify persisted record counts prior to downstream consumption.

🧭 Scope & Architectural Approach

Orchestrate ingestion workflows with Azure Data Factory, persist raw and curated data in ADLS Gen2, execute distributed transformations using Azure Databricks & PySpark, and govern storage access via Unity Catalog.

05 · Engineering in the Trenches

Real-world bottlenecks & how I solved them

Production data engineering rarely follows a straight tutorial path. These six architectural hurdles required root-cause investigation and modern Azure adaptation.

01

Schema & File Format Drift

Source feeds varied across delimiters, column naming conventions, and date encodings. I profiled each raw feed individually, isolated ingestion paths by domain, and enforced explicit schema casting in PySpark.

02

Conflicting Time Grains (Daily vs. Weekly)

Hospital metrics arrived at both daily and weekly cadences. To prevent double-counting or cartesian fan-out, I segregated daily and weekly pipelines in the Silver layer and modeled distinct Gold fact tables.

03

Deprecated DBFS Mount Restrictions

Legacy tutorial patterns relied on dbfs:/mnt mounts unsupported in modern workspaces. I re-architected storage access using Unity Catalog Storage Credentials, External Locations, and managed Volumes.

04

Storage Authorization & Path Scoping

Permission errors revealed tight coupling between managed identities, RBAC roles, and External Location URL prefixes. I audited credential bindings and aligned directory scopes across ADLS containers.

05

Refactoring Flat Lake Directories

Replacing ad-hoc tutorial paths with domain-aligned landing/, processed/, and curated/ hierarchies improved discoverability, simplified RBAC policies, and clarified data lineage.

06

End-to-End Output Reconciliation

Rather than trusting green pipeline runs blindly, I built explicit post-write validation checks verifying Parquet schema integrity and exact row counts across all 7 Gold tables.
